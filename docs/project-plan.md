# 项目贡献、简历与后续路线

## 项目定位

**基于 Needle 的深度学习框架与 Transformer GPU 算子优化。**

以 CMU 10-714 课程框架为基础，展示从算法与硬件分析、自写 CUDA 内核，到框架集成、误差验证、性能消融的完整过程。近期成果集中于 **Transformer 前向**。

## 已完成的项目贡献

1. **GEMM 优化链**：FP32 SIMT 的分块、寄存器复用、向量化访存和双缓冲；进一步实现 FP16 输入、FP32 累加的 WMMA 与 cp.async 双缓冲。
2. **框架集成**：统一 MatMul/Linear 分派，显式精度策略，CPU 回退、不规则尺寸和非连续输入支持；统一两份课程源码及构建入口。
3. **融合算子**：Online Softmax 注意力和 LayerNorm 前向；在同权重 TransformerLayer 上逐步启用并测量收益。
4. **实验工程**：FP64 数值参考、同精度 cuBLAS 对照、内核/框架两级计时、三轮重复实验、机器可读结果和源码哈希。
5. **验证与分析**：110 项测试通过、三种 Compute Sanitizer 检查通过；Nsight Systems 记录真实 CUDA 时间线，识别分配/释放和注意力开销。

Tensor Core 算法来自作者此前的 [GEMM 笔记](https://neu-china-top-fei.github.io/2026/06/04/DLsysSet/GEMM/)。框架基础来自 CMU 课程；简历中应明确这种继承关系，个人贡献表述需与实际参与部分一致。

## 可以使用的简历表述

> **基于 Needle 的深度学习框架与 CUDA 算子优化**  
> 基于 CMU 10-714 课程框架，扩展 CUDA GEMM 与 Transformer 前向算子，实现共享内存分块、寄存器复用、WMMA Tensor Core 及 cp.async 双缓冲，并接入统一 MatMul 路径。  
> 在 RTX 4060 Laptop 上，2048³ GEMM 使用 FP16 输入 / FP32 累加，预打包内核达到 14.40 TFLOPS；包含转换和分配的框架调用相对 FP32 SIMT 加速 4.73×，相对 FP32 输出 L2 误差约 2.94e−4。  
> 结合注意力和 LayerNorm 融合，将指定 TransformerLayer（B=8/S=64/D=256/H=8）同权重前向由 22.41 ms 降至 2.81 ms，加速 7.98×，相对 L2 误差约 5.62e−4；建立三轮消融实验与 CUDA 正确性/内存同步检查。

如果版面只有两行，保留内核技术和模型结果，并在项目链接里提供实验配置；不要省略 FP16/FP32 精度约定。14.40 TFLOPS 是预处理后的**内核**指标，不能写成包含所有框架成本的吞吐率。

## 面试时能展开的三个问题

- **为什么原始 GEMM 慢？** 结合线程/warp 分工、数据复用、共享内存和寄存器分析，再解释 Tensor Core 的输入精度与矩阵指令约束。
- **为什么内核更快，模型收益却有限？** medium 配置仅替换 TC GEMM 为 1.74×；加入注意力与 LayerNorm 融合才达到 7.98×。用同权重消融和真实时间线解释。
- **与成熟库差在哪里？** 2048³ 同精度 cuBLAS 约 0.611 ms，自写 TC 内核约 1.193 ms；当前四个 warp、固定 tile 和布局尚有改进空间，硬件计数器验证待权限开放。

## 下一阶段按证据推进

1. **缓冲复用 / 权重预打包**：时间线显示每次前向仍有 40 次分配和 40 次释放。先处理静态推理权重和临时工作区，明确缓存失效与生命周期。
2. **协作分块注意力**：现有融合注意力占优化后 GPU kernel 时间约 63.9%，优先验证跨线程/warp 的 K/V 复用。
3. **形状相关的 GEMM 分派**：依据已测的小矩阵、矩形和边缘尺寸决定阈值，避免仅凭理论峰值切换。
4. **训练作为单独目标**：只有补齐 GPU backward、混合精度策略和收敛实验后，才扩展成训练系统项目。

本次没有宣称超越 cuBLAS、完整复现 FlashAttention 或实现高性能 GPU 训练。性能表格与误差的完整证据见 [实测报告](performance.md)。
