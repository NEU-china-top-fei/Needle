## 3. 原始版本（use_flash_attn=False）耗时拆解

### 3.1 按功能模块拆解

> 比例由 cProfile cumtime 计算，应用于 GPU wall time `21.38 ms`

```
TransformerLayer.forward  21.38 ms (100%)
│
├── AttentionLayer.forward  15.61 ms (73%)
│   ├── LayerNorm ×3          ≅ 8.0 ms (37%)  ← prenorm_q/k/v
│   ├── Linear ×4             ≅ 3.0 ms (14%)  ← q/k/v/out projections
│   ├── MHA forward           4.92 ms (23%)   ← 核心注意力计算
│   │   ├── custom matmul     2.99 ms (14%)   ← 5D broadcast 实现 Q@K^T
│   │   ├── softmax           1.92 ms ( 9%)   ← 含 realize_cached_data() 同步
│   │   └── custom matmul     (包含在上)      ← 5D broadcast 实现 P@V
│   └── reshape/permute       ≅ 0.7 ms ( 3%)  ← 维度变换
│
└── FFN sub-layer            5.77 ms (27%)
    ├── LayerNorm ×1          ≅ 2.7 ms (12%)  ← self.norm
    ├── Linear ×2             ≅ 1.7 ms ( 8%)  ← linear1 + linear2
    └── Dropout/ReLU/residual ≅ 1.4 ms ( 7%)
```

### 3.2 按操作类型拆解（跨模块汇总）

| 操作类型 | 占比 | 估算耗时 | 说明 |
|----------|------|----------|------|
| **LayerNorm (4次)** | ∼37% | ∼7.9 ms | 每次 norm 包含 mean→sub→square→sum→sqrt→div→mul→add 8 个 op |
| **Linear matmul (6次)** | ∼14% | ∼3.0 ms | 每个 Linear 是一次 `matmul(X, W)`，底层走 `ndarray.__matmul__` |
| **MHA broadcast matmul** | ∼14% | ∼3.0 ms | `MultiHeadAttention.matmul()` — 5D broadcast→mul→sum |
| **MHA softmax** | ∼9% | ∼1.9 ms | 含 `realize_cached_data()` 导致的 host-device sync |
| **Dropout (3次)** | ∼4% | ∼0.9 ms | rand + mask + mul |
| **ReLU** | ∼1% | ∼0.2 ms | 单次 element-wise |
| **Residual add (3次)** | ∼2% | ∼0.4 ms | element-wise add |
| **reshape/permute** | ∼3% | ∼0.6 ms | 维度变换 + compact |
| **Metadata overhead** | ∼16% | ∼3.4 ms | make(alloc) + compact + is_compact + compact_strides + realize_cached_data |
| | | | |
| **合计** | **100%** | **21.4 ms** | |

### 3.3 Metadata overhead 详解

cProfile 中元数据相关函数的调用次数和累计时间（flash_attn=False）：

| 函数 | 调用次数 | cumtime | 含义 |
|------|----------|---------|------|
| `make` (分配) | 191 | 0.004s | 每次创建 NDArray 都调用 `cudaMalloc` |
| `compact` (紧凑化) | 142 | 0.005s | 检查+复制到紧凑布局 |
| `is_compact` (判断) | 189 | 0.004s | 检查 strides 是否连续 |
| `compact_strides` (计算) | 291 | 0.003s | 计算紧凑 strides |
| `realize_cached_data` | 348 | 0.018s | 触发延迟计算的执行 |
| `make_from_op` | 134 | 0.020s | 创建 Tensor node |

这些函数占了整个调用栈的 30%+ CPU 时间，且大量交互（每创建一个 NDArray 都要 `make` → `is_compact` → `compact_strides` → 可能 `compact`）。

## 4. Flash 版本（use_flash_attn=True）耗时拆解

```
TransformerLayer.forward  12.87 ms (100%)
│
├── AttentionLayer.forward  8.62 ms (67%)
│   ├── LayerNorm ×3          ≅ 5.3 ms (41%)  ← 没变
│   ├── Linear ×4             ≅ 2.1 ms (16%)  ← 没变
│   ├── FlashAttention        ≅ 0.4 ms ( 3%)  ← ★ 从 4.92ms 降到 0.4ms
│   └── reshape/permute       ≅ 0.8 ms ( 6%)
│
└── FFN sub-layer            4.25 ms (33%)
    ├── LayerNorm ×1          ≅ 1.8 ms (14%)
    ├── Linear ×2             ≅ 1.2 ms ( 9%)
    └── Dropout/ReLU/residual ≅ 1.3 ms (10%)
```

### 4.1 Flash 版本的变化

| 指标 | orig | flash | 节省 |
|------|------|-------|------|
| MHA 耗时 | 4.92 ms | 0.40 ms | **−4.52 ms (−92%)** |
| TL 总耗时 | 21.38 ms | 12.87 ms | **−8.51 ms (−40%)** |
| 函数调用 | 7,208 | 5,808 | **−1,400 (−19%)** |
| Metadata 调用 | 基准 | −23% | make: 191→153, compact: 142→121, is_compact: 189→162 |

## 5. 瓶颈排名（Flash 版本，12.87ms）

```
LayerNorm (4次)           ████████████████████████████  41%  ← #1 瓶颈
Linear matmul (6次)       ██████████                    16%  ← #2 瓶颈
Metadata (alloc/compact)  ██████████                    16%  ← #3 瓶颈
Dropout/ReLU/residual     ████████                      12%  ← #4
reshape/permute           ████                           6%
FlashAttention            ██                             3%  ← 已大幅优化
其他                       ████                           6%
```

### 结论

1. **LayerNorm 是第一瓶颈**（41%）：每次 norm 拆成 8 个 element-wise op，4 次 norm 共 32 个 kernel launch。应写 CUDA kernel 融合 mean/var/scale/shift 为一次 launch。

2. **Linear/matmul 是第二瓶颈**（16%）：6 个 `matmul(X, weight)`，每个走 `ndarray.__matmul__` → `device.matmul()`，要先 `compact` 再调用。替换为直接 cuBLAS `cublasSgemm` 可省掉 metadata 开销。

3. **Metadata 是第三瓶颈**（16%）：`make`（cudaMalloc）+ `compact` + `is_compact` 在每次 op 中重复出现。用内存池（bump allocator）可减少 50%+ 的分配开销。

4. **FlashAttention 已不再是瓶颈**（3%）：MHA 从 23% 降到 3%，优化效果显著。剩余差距主要在上面三个方向。
